Guia de implementação da API

Loja de jogos online — material de apoio para o aluno desenvolvedor back-end
Importante: o projeto contém o front-end Windows Forms e define os endereços que a API deverá atender. O aluno deve implementar essas rotas no projeto back-end e iniciar a API em http://localhost:5212, ou ajustar o endereço no front-end. Os links para localhost abrem a rota no navegador (requisição GET). POST, PUT e DELETE são enviados pelos botões do Windows Forms; os links de código mostram onde essas chamadas são feitas.

Os links abaixo abrem o arquivo Form1.cs no repositório GitHub, diretamente na região da chamada correspondente.

As rotas e os campos de cada entidade são configurados em jogos, categorias, estúdios e usuários.

Rotas que o aluno deve implementar

Todos os recursos usam as mesmas operações REST. Troque {id} por um ID existente para testar GET por ID ou DELETE.

RecursoGET listaGET por IDPOSTPUTDELETE

Os links locais funcionam quando a API estiver executando nessa porta. Um erro 404 indica que a rota ainda não foi criada ou que o caminho/porta da API é diferente.

Campos esperados nos dados

  • Jogo: nome (texto), descricao (texto opcional), preco (decimal), categoriaId (inteiro) e estudioId (inteiro).
  • Categoria: nome (texto) e descricao (texto opcional).
  • Estúdio: nome (texto) e pais (texto opcional).
  • Usuário: nome, email e senha. A senha é enviada no cadastro e não deve ser retornada em respostas de consulta.

Exemplo de corpo JSON para cadastrar um jogo:

{
  "nome": "Jogo de exemplo",
  "descricao": "Descrição do jogo",
  "preco": 79.90,
  "categoriaId": 1,
  "estudioId": 1
}

Para a tela Explorar, retorne uma lista JSON, por exemplo [{ "id": 1, "nome": "Jogo de exemplo" }]. Também é aceito um objeto com a lista dentro de data.
